# 审批、导入与变更

## 三种记录分别生效

项目基准批准表示用户接受当前共同美术规则；任务采用表示总控接受某返回物用于整合；领域批准表示用户接受角色／场景／道具某阶段或某张图片。不能互相替代。记录应包含对象、版本、依据及用户原话或原批准记录。推荐、模型审查、继续运行、文件更新和批量交付都不自动构成用户批准。

图片相关登记必须有真实文件和对应检查；未回流只记提示词已交，未查看不记审查通过。子插件没有统一的审批脚本时保留其原始确认和基准记录，不为了统一索引伪造一条批准。母索引中的批准状态必须能追溯到该记录。

## 显式导入已有角色项目

用户指定导入后，读取角色 `project.json` 及其原记录；核对母项目剧本来源哈希、角色／状态 ID 与交付文件哈希。同源、同 ID、实际文件未变的批准可引用保留，其他项作为待匹配或待复核，不因导入成功自动批准。原项目保留，母项目只存映射和来源引用。

同名不等于同一资产，旧 ID 不得靠重命名匹配。哈希变化、来源无法定位或批准记录缺失时列出具体差异，人工判断只针对受影响项。跨来源迁移需要显式对应和用户决定；缺失文件保留缺失状态，不声称资产齐全。

## 局部失效

新版本保留旧基准与结果。来源事实、项目基准或资产结构变化时，沿任务和资产依赖标记直接及间接影响项待复核，尚可复用的领域批准保留引用但说明当前适用范围。仅改交付文件位置而内容哈希相同，不构成重新设计。

身份变化通常影响角色下游及依赖该身份的关联项；身体尺度变化影响相关全身、服饰、握持与空间关系；服饰状态变化仅从该状态及其真实依赖传播。环境打光不改变固有色、道具状态不自动改变基础身份。具体边界先遵守子插件的版本合同，再处理跨域关系。

## 交付状态

统一索引分别展示设计／提示词交付、待选方向、待回图、领域批准和复核状态。整合采用不是全流程完成；取消或失败的任务保留记录。用户只要求文字产物时，文字范围实际齐备可交付，不能把下游图片等待夸大成该任务失败，也不能称图片已完成。
